`<moul-tracing-beam>` draws a line in the gutter beside an article. As the reader scrolls, the line fills from the top with a gradient, its bright head travelling down beside the text they are reading, and the dot at the top lights once they start. It suits a long post, a changelog or a step-by-step guide.

```

  <p>The bus leaves the Central Market at seven…</p>

  <h2>Day two: Bokor</h2>
  <p>The road up the mountain climbs through cloud forest…</p>
</moul-tracing-beam>
```

The element adds a gutter on the inline start, the right in right-to-left text, and the line runs the full height of the article. It follows the content as images load or the text reflows, and it follows the nearest scroll container: the page, or a panel with `overflow: auto` as in the demo.

## When the beam fills

The beam starts when the top of the article comes halfway down the view, and it is full when the end of the article comes into view. Because it ends there, rather than when the end reaches the middle of the screen, it always fills, even when the article is the last thing on the page.

`--tracing-beam-start` moves the starting line: a percentage of the view, or a length from its top.

```css
moul-tracing-beam {
  --tracing-beam-start: 30%;
}
```

A short article, one that fits in the view below that line, fills from the moment it is fully in view until its top reaches the line.

## Styling

`--tracing-beam-from` and `--tracing-beam-to` set the two ends of the gradient; the head and the lit dot take the second. `--tracing-beam-track` colours the unfilled line. `--tracing-beam-gutter` sets the space the line sits in, `--tracing-beam-width` its thickness and `--tracing-beam-dot-size` the dot. Every part is also reachable through `::part()`.

## Cost

Where the browser has scroll-driven animations (Chrome and Edge 115, Safari 26), a view timeline in CSS moves the beam and no script runs while the reader scrolls. Elsewhere a passive scroll listener moves it once per frame. Either way the beam is a strip moved by a transform, so the page is never laid out again as it fills.

## Accessibility

The line, the beam and the dot are decorative and hidden from assistive technology. The element is never focusable and adds no role, so the article is read, and its links reached with Tab, as if the element were not there. Where the system forces its own colours, as in Windows high contrast mode, the line and the beam are drawn in system colours. When printing, the line is left out.

Under `prefers-reduced-motion: reduce` the beam keeps following the scroll, because the reader is the one moving it; it has no easing, spring or lag of its own, so it is never ahead of or behind the page. The glowing head is not drawn, and the line simply fills.

## Attributes and properties

`<moul-tracing-beam>` has no attributes of its own; style it with the CSS properties below.

| Slot | Description |
| :-- | :-- |
| (default) | The article: headings, paragraphs, images, any content. |

| Part | Description |
| :-- | :-- |
| `rail` | The column in the gutter that holds the line and the dot. |
| `track` | The unfilled line, the full height of the content. |
| `beam` | The filled part of the line. |
| `head` | The glowing point at the end of the beam. |
| `dot` | The ring at the top of the line. |
| `dot-light` | The light inside the dot, shown once reading starts. |
| `content` | The wrapper round the article, after the gutter. |

| CSS property | Description | Default |
| :-- | :-- | :-- |
| `--tracing-beam-start` | How far down the view the article's top must come before the beam starts. | `50%` |
| `--tracing-beam-gutter` | The space on the inline start that holds the line. | `2.5rem` |
| `--tracing-beam-width` | The thickness of the line. | `2px` |
| `--tracing-beam-dot-size` | The size of the dot at the top. | `1.125rem` |
| `--tracing-beam-from` | The colour at the top of the beam. | `var(--color-chart-5)` |
| `--tracing-beam-to` | The colour at the head of the beam and of the lit dot. | `var(--color-chart-4)` |
| `--tracing-beam-track` | The colour of the unfilled line. | `var(--color-border)` |
