`<moul-scroll-progress>` is a thin bar that fills from the inline start as the reader scrolls, so a long article or a landing page shows how far through it they are. On its own it follows the page, fixed along the top of the viewport; with `for` it follows a scroll container instead. Scroll the box below.

It lives in the effects entry, with the rest of the landing kit:

```js
import '@moul-dev/web-component/effects'
```

For the page, put one anywhere in the body. It is fixed along the top of the viewport, full width, above the page content and below dialogs:

```html
<body>
  <moul-scroll-progress></moul-scroll-progress>
  …
</body>
```

## Placement

`placement` says where the bar sits:

- `top` (the default) is fixed along the top of the viewport.
- `bottom` is fixed along the bottom of the viewport.
- `inline` sits in the normal flow at the width of its parent, for you to place. Make it sticky at the top of a scroll panel, or put it at the foot of a sticky site header so the bar runs under the header rather than over it.

```html
<header class="site-header">
  <nav>…</nav>
  <moul-scroll-progress placement="inline"></moul-scroll-progress>
</header>
```

## Following a scroll container

`for` takes the id of a scroll container in the same document or shadow root, and the bar follows that container instead of the page. Changing `for` switches to the new container. If no element has that id yet, the bar stays empty until one appears, then follows it.

```html
<div id="changelog" style="height: 20rem; overflow: auto">
  <moul-scroll-progress for="changelog" placement="inline" style="position: sticky; top: 0"></moul-scroll-progress>
  …
</div>
```

## Tone and colour

`tone` picks the colour of the fill: `primary` (the default), `accent`, `success`, `warning` or `error`. `--scroll-progress-color` takes any colour instead, `--scroll-progress-height` sets the thickness (3px by default), and `--scroll-progress-track` colours the part not yet filled (transparent by default).

## How it fills

Where the browser has scroll-driven animations, a native scroll timeline fills the bar and no script runs while the reader scrolls. Elsewhere a passive scroll listener updates it once per frame. Either way the progress, from 0 to 1, is the `--scroll-progress` custom property on the element, and the bar is scaled by it from the inline start: the left edge, or the right edge in right-to-left text.

## Accessibility

`<moul-scroll-progress>` is decoration: it carries `aria-hidden="true"` and is never focusable. The scrollbar and the reader's own place in the text already say where they are, so announcing a percentage would only repeat it. If progress is information the reader needs, such as an upload, use `<moul-progress-bar>` with a label.

Under `prefers-reduced-motion: reduce` the bar still follows the scroll, because the reader is the one moving it. It adds no easing or spring of its own, so it is never ahead of or behind the page.

## API reference

| Attribute | Property | Type | Default |
| :-- | :-- | :-- | :-- |
| `for` | `htmlFor` | `string`, the id of a scroll container | `''` (the page) |
| `placement` | `placement` | `'top' \| 'bottom' \| 'inline'` | `'top'` |
| `tone` | `tone` | `'primary' \| 'accent' \| 'success' \| 'warning' \| 'error'` | `'primary'` |

| Part | Description |
| :-- | :-- |
| `base` | The track: the full length of the bar. |
| `bar` | The fill, scaled from the inline start by the scroll progress. |

| CSS property | Description |
| :-- | :-- |
| `--scroll-progress-color` | The colour of the fill. Defaults to the `tone` colour. |
| `--scroll-progress-height` | The thickness of the bar. Defaults to `3px`. |
| `--scroll-progress-track` | The colour of the part not yet filled. Defaults to `transparent`. |
