Until this release, Moul UI only worked inside React. Its components were React components built on React Aria, styled by StyleX at compile time, and charted with Recharts. Any project that did not run React (an Astro site, a Vue app, a server-rendered admin page, a plain HTML form) could not use a single button from it.

A design system meant to be one consistent baseline across every web stack cannot depend on one framework's component model. So this release replaces the entire implementation.

Every component is now a standard custom element built on **Lit 3** and **Shadow DOM**. Styling comes from a runtime CSS token layer (`light-dark()` + `oklch()`), and behavior builds on native browser primitives. React, React Aria, StyleX, and Recharts are gone from both the library and the documentation site, which has been rebuilt on **Astro Starlight**.

This is a breaking release. If you use Moul UI from React today, read [Migrating from v2026.9.28](#migrating-from-v2026928) before upgrading.

## Native Custom Elements on Lit 3

The library now registers **79 custom elements**, all prefixed `moul-`. Import the package once and they work anywhere HTML runs:

```ts
import '@moul-dev/ui/style.css' // design tokens
import '@moul-dev/ui'           // registers every <moul-*> element
```

```html
<moul-button variant="primary">Deploy</moul-button>
<moul-text-field label="Project name" description="Lowercase, no spaces" is-required></moul-text-field>
```

Simple values travel as reflected attributes (`is-disabled`, `error-message`, `trend-value`). Arrays and objects such as chart data are set as JavaScript properties (`chart.data = [...]`). Components report changes through standard DOM events such as `press`, `change`, `selectionchange`, and `inputchange`.

Behavior that React Aria used to emulate now comes from the browser:

- **Overlays:** Modal, alert dialog, drawer, and command palette are built on `<dialog>`. Popovers, tooltips, selects, combo boxes, the date picker, and toasts open through the Popover API in the top layer, without portals; popovers and tooltips position themselves with CSS Anchor Positioning.
- **Forms:** Inputs are form-associated through `ElementInternals`. A `<moul-text-field>` or `<moul-checkbox>` inside a regular `<form>` submits its value and reports validity like a native input.
- **Shared behavior:** Five Lit reactive controllers (`PressController`, `LayoutIndicatorController`, `OverlayPresenceController`, `NumberSpringController`, and `FormInternalsController`) carry press and hover state, breakpoints, enter and exit animation, spring-animated numbers, and form association across components. They are exported for building your own elements.
- **Editor tooling:** The build emits a Custom Elements Manifest (`dist/custom-elements.json`), so editors and linters can autocomplete tags, attributes, and events.

## A Runtime Token Layer Instead of Compiled Styles

StyleX resolved styles at build time, which meant theming required rebuilding. The new `@moul-dev/ui/style.css` defines every color, radius, shadow, and font as a CSS custom property on `:root`. Colors are authored in `oklch()` and resolved per scheme with `light-dark()`, so one declaration covers both themes[^1].

Shadow DOM keeps each component's internals isolated from page styles, while the tokens pierce the boundary by design. Override a token on `:root` or any ancestor and every component below it follows:

```css
:root {
  --brand-font-family: 'Inter', sans-serif;
}

.billing-panel {
  --color-chart-sequential: var(--color-chart-5);
}
```

Components draw from one shared set of five semantic tones (`primary`, `accent`, `success`, `warning`, `error`) and five visual variants (`solid`, `flat`, `shadow`, `bordered`, `glass`). Charts are drawn with `d3-scale` and `d3-shape` instead of Recharts, and read their palette from the same tokens.

## New Visualizations: Heatmap, Funnel, and Stat

Three data components arrive or change substantially this cycle.

**`<moul-heatmap-chart>`** colors a grid of days by activity: 53 weeks by default, newest on the right. Set `mode="hour"` and the same timestamps fold into a weekday-by-hour punch card. Active days split into four levels by quartile, so one exceptional day does not wash out the rest. The grid is an ARIA `grid` with a single tab stop and arrow-key navigation by day and week.

**`<moul-funnel-chart>`** draws ordered steps as centered bars sized against the first. A narrowing neck between steps carries each step's drop-off, and a summary names the overall conversion and the steepest drop. Steps share one ordinal color ramp (`--color-chart-ordinal-from` to `--color-chart-ordinal-to`) instead of unrelated hues.

**`<moul-stat>`** is rebuilt. New values count in with a spring. The sparkline runs to the card's edges and can be scrubbed by pointer or keyboard, and screen readers announce it as a slider. `is-lower-better` flips the trend colors for metrics like churn and latency.

The logs viewer's detail drawer now opens on row click, swaps its content when you pick another row, and closes on Escape, with focus tracked through shadow roots back to the row you came from.

## Documentation on Astro Starlight

The documentation site moved from Waku and Fumadocs to Astro Starlight:

- **Previews from source:** Component previews import the library straight from `ui/src`, so the docs can never drift behind a stale `dist` build, and component edits hot-reload in the docs.
- **Bilingual by default:** English and Khmer content migrated to Starlight's locale routing, and Khmer pages are now set in Noto Sans Khmer.
- **Theme Studio:** The `/theme` page is rebuilt as a live inspector and palette tuner for the CSS token layer.
- **One component order:** The docs sidebar reads its categories from the same list as the component sandbox, which is now plain HTML and Lit.
- **AI context:** `/llms.txt`, `/llms-full.txt`, and `AGENTS.md` now describe custom elements, so assistants generate `<moul-*>` markup instead of React components.

## Migrating from v2026.9.28

v2026.9.28 is the last React release. To stay on React, pin it:

```bash
bun add @moul-dev/ui@2026.9.28
```

To move to custom elements:

- **Imports:** Import `@moul-dev/ui` once for registration and `@moul-dev/ui/style.css` for tokens. The `@moul-dev/ui/tokens`, `@moul-dev/ui/tokens.stylex`, `@moul-dev/ui/theme.css`, and `@moul-dev/ui/style` entry points are removed.
- **Markup:** Replace PascalCase components with tags. Boolean props become attributes (`isDisabled` → `is-disabled`), and handlers become DOM listeners (`onPress` → a `press` event listener).
- **Data:** Assign arrays and objects as properties (`chart.data = [...]`) rather than passing them as attributes.
- **Field helpers:** `Label`, `Description`, `FieldError`, and `ErrorMessage` are gone. Fields take `label`, `description`, and `error-message` attributes directly.
- **Removed components:** `Autocomplete` is covered by `<moul-combobox>`, which filters as you type and fires `inputchange` for remote suggestions. `ListBox` and `DateField` have no direct replacement yet; `<moul-date-picker>` covers date entry.
- **React apps:** React 19 renders custom elements and passes them properties, so `<moul-button>` works in JSX without a wrapper. Moul UI no longer ships React adapters.

## Between Releases: The September React Line

The React line kept shipping between v2026.09.07 and this rewrite (v2026.9.10 through v2026.9.28). It added an `Autocomplete` component, `onAction` on `ComboBox`, a `ListBox`, and the `--brand-font-family` token, along with tertiary tab updates, an SSR fix for `Sidebar`, and drawer and color fixes.

`--brand-font-family` carries over to the new token layer. The rest stays with the React line.

## On Building on the Platform

React Aria made accessible overlays, focus management, and form semantics dependable at a time when the browser offered little help. The platform has since caught up: `<dialog>`, the Popover API, anchor positioning, and `ElementInternals` now cover much of what that layer used to emulate.

Building on them directly means less code between the browser and the person using it, and components that behave the way native controls already taught them to expect.
