The newest Moul UI on npm is still `1.0.0-alpha.1`. The `v1.0.0-alpha.2` tag made a GitHub release, but publishing to npm was a manual step that never happened, and in the meantime the library went from 79 elements to 196.

That much new surface deserves a release candidate rather than another alpha. `1.0.0-rc.1` is what I intend to ship as `1.0.0` unless testing turns up a problem, so this is the build to try in a real app and report back on. If you are coming from alpha.1, it also includes alpha.2's [collapsed sidebar fixes](/km/changelog/1-0-0-alpha-2).

The whole catalogue is [further down this page](#every-component-live), one live preview per component.

## Three Imports Instead of One

Most of the new elements are motion: text effects, backgrounds, pointer and scroll effects, particles, a globe. An admin screen needs none of it, so none of it is in the main import.

| Import | Registers |
| --- | --- |
| `@moul-dev/web-component` | 121 app elements: forms, overlays, feedback, data, charts, the AI kit and blocks |
| `@moul-dev/web-component/effects` | 60 motion and landing-page elements, and the motion controllers they share |
| `@moul-dev/web-component/canvas` | 15 canvas and WebGL elements, each downloaded the first time its tag appears |

Each import is built in its own pass. Every published file has a byte budget, and the build fails when a file grows past it, so the main import cannot quietly start paying for the effects.

The canvas import registers nothing up front. It is a loader of about 2 KB that watches the page and downloads an element's own file the first time its tag appears, so a page without `<moul-globe>` never loads the globe.

```ts
import '@moul-dev/web-component/style.css'
import '@moul-dev/web-component'         // forms, overlays, data, charts, AI kit
import '@moul-dev/web-component/effects' // only on pages that use effects
import '@moul-dev/web-component/canvas'  // <moul-globe> downloads when it appears
```

The loader cannot see inside a shadow root. There, call `watchCanvasElements(shadowRoot)`, or import one element directly with `import '@moul-dev/web-component/canvas/globe'`.

Every element ships with the same five things, and a test fails until it does: a description in the Custom Elements Manifest, keyboard and screen reader behaviour, a reduced-motion path, light and dark themes from tokens alone, and a docs page with a test. The 79 elements that predate the rule meet it too.

## Existing Elements, Extended

These are additions. One CSS part on `<moul-button>` was renamed; it is under Upgrading.

- **`<moul-button>`:** `state` (`idle`, `pending`, `success`, `error`) with an icon that morphs between a loader, a check and an alert mark, and a slot per state for its label. `run(task)` drives the states from a promise. For landing pages, `effect` (`shimmer`, `rainbow`, `neon`), `is-pulsing` and a `hover` slot.
- **`<moul-table>`:** search (`is-searchable`), column filters (`filterOptions`), expandable rows (`renderExpanded`), cards below about 480px wide, a `toolbar` slot, `is-dense`, `skeleton-rows`, and `is-manual`, which leaves search, filters and sorting to your server.
- **`<moul-drawer>`:** `is-sheet` makes it a bottom sheet you drag down to dismiss.
- **`<moul-toast>` and `<moul-toast-region>`:** toasts swipe away, `show-countdown` draws the time left (an undo toast, with an Undo button in the action slot), and `is-stacked` collapses the region into a deck.
- **`<moul-tooltip>`:** `follow="pointer"` and `is-rich` with a `media` slot.
- **`<moul-badge>`:** `count` rolls to each new value (`99+` past `max`), and `is-live` adds a pulsing dot.
- **`<moul-spinner>`:** `variant` picks `ring`, `dots`, `shape` or `orbit`.
- **`<moul-text-field>`:** `placeholders` rotate through hints, and `vanish()` or `vanish-on-submit` scatters the typed text.
- **`<moul-search-field>`:** `is-expandable` starts as a round search button that opens into the field.
- **`<moul-card>`:** `effect` takes `spotlight`, `glare` and `glow`.
- **Charts:** dragging scrubs `<moul-area-chart>` and `<moul-line-chart>` (a `role="slider"` for the keyboard), `<moul-line-chart is-live>` takes readings through `push()`, and `<moul-doughnut-chart>` becomes a gauge when you set `value`.

## What It Costs

More elements in the main import make it heavier. Since alpha.2 it went from 112 KB to 236 KB gzipped, and the CDN file from 155 KB to 269 KB.

The bundles would be heavier still. Lit ships its `css` templates as written, comments and indentation included, so the build now minifies them, which takes more than 140 KB off each main bundle before compression.

`effects.js` is about 100 KB gzipped, and only pages that import it pay for it. With the canvas import, a page pays for the elements it actually shows: each one is 2.7 to 6.5 KB gzipped on the CDN, plus an 11 KB chunk they share.

## A Smaller, More Accurate Manifest

Agents choose elements from `custom-elements.json`, and it carried noise. Lit fields declared `{ state: true }` showed up as public attributes, 83 of them across 47 elements, such as `hasToolbarSlot` on `<moul-table>`. Nine elements listed a `type` event that never fires, because the analyzer read `new CustomEvent(type, …)` in a shared helper as an event called `type`.

Both are filtered out now, and so are private members. The file is written without indentation, which takes it from 2.6 MB to about 1 MB. `llms-full.txt` has the same fixes, since it is generated from the manifest.

The npm page lists every element, and that list is now generated from the manifest too. Until now it had stopped at 79.

## How Releases Ship Now

Pushing a `v*` tag now runs the tests, builds the library, checks the generated docs against the manifest, publishes the tarball to npm, and attaches the same tarball to a GitHub release. Publishing uses npm's trusted publishing: the workflow trades a GitHub token for a short-lived npm token, so the repository stores no npm token.

If a later step fails, re-running the job skips publishing, because npm already has the version.

## Upgrading

- **Install:** `bun add @moul-dev/web-component@1.0.0-rc.1`.
- **From alpha.1:** read the [alpha.2 notes](/km/changelog/1-0-0-alpha-2) too: remove CSS that centered collapsed sidebar rows, and position the collapse toggle through its wrapper.
- **`<moul-button>` parts:** `::part(spinner)` is gone. The pending loader is now a `<moul-icon-morph>` in `::part(icon)`, which also shows the success and error marks. `is-pending` still means `state="pending"` and still blocks presses.
- **Effects and canvas:** nothing changes unless you import them.
- **Tools that read the manifest:** it is compact JSON now. Internal state fields, private members and the phantom `type` events are gone.

The main import still registers every element, so a page with one button carries the chat view as well. Per-element imports come next, using the same build the canvas elements already have.
