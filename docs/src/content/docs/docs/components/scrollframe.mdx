It lives in the effects entry, with the rest of the motion elements:

```js
import '@moul-dev/web-component/effects'
```

```html
<moul-scroll-frame>
  <h2 slot="header">Every booking, one screen</h2>
  <moul-browser-frame url="trips.example.com/today">
    <img src="/dashboard.png" alt="The bookings dashboard with today's arrivals" />
  </moul-browser-frame>
</moul-scroll-frame>
```

Put the screen in the default slot: a [browser frame](/docs/components/browserframe/), a [phone frame](/docs/components/phoneframe/), an image or any box. The `header` slot is optional; without it the screen tilts alone.

## When it lies flat

The tilt follows the element's passage through the viewport, or through the scroll container it sits in. It starts as the top of the element enters at the bottom of the view, and the screen is flat by the time the middle of the element reaches the middle of the view. From there on it stays flat, so a reader who has scrolled past sees a plain screen. Scrolling back up tilts it back.

## How far it tilts

`tilt` is how far back the screen starts, in degrees, from 0 to 60; it is 20 by default. `--scroll-frame-scale` is the scale it starts at, 1.05 by default, easing to 1 as it lies flat. `--scroll-frame-perspective` is the distance of the viewer from the screen: a smaller value looks deeper. `--scroll-frame-header-shift` is how far below its place the heading starts.

```html
<moul-scroll-frame tilt="35" style="--scroll-frame-scale: 0.9; --scroll-frame-perspective: 800px">
  …
</moul-scroll-frame>
```

## Cost

Where the browser has scroll-driven animations, the tilt and the heading are CSS animations on a view timeline: the browser runs them as the reader scrolls, and no script runs at all. Elsewhere a passive scroll listener writes the progress once per frame, and the same transforms are worked out in CSS. Either way only transforms change, so the page is never laid out again.

## Styling

`::part(base)` is the wrapper whose passage drives the tilt, `::part(header)` holds the heading and `::part(frame)` is the layer that tilts. `--scroll-frame-gap` sets the space between the heading and the screen.

## Accessibility

The element is never focusable and adds no role. The heading and the screen are read in order with their own semantics, and anything focusable inside is reached with Tab as usual, tilted or not. Give a screenshot alt text that says what it shows.

Under `prefers-reduced-motion: reduce` the screen is flat and the heading in place from the start, and no script follows the scroll. The element reacts to the setting as soon as it changes.

## Attributes and properties

| Attribute | Property | Type | Default |
| :-- | :-- | :-- | :-- |
| `tilt` | `tilt` | `number` (degrees, 0 to 60) | `20` |
| | `isNative` | `boolean`, read only: a view timeline drives the tilt | depends on the browser |

| Slot | Description |
| :-- | :-- |
| (default) | The screen: a browser frame, a phone frame, an image or any box. |
| `header` | A heading or intro above the screen that rises into place. |

| Part | Description |
| :-- | :-- |
| `base` | The wrapper whose passage through the viewport drives the tilt. |
| `header` | The wrapper of the `header` slot. |
| `frame` | The wrapper that tilts; it holds the screen. |

| CSS property | Description | Default |
| :-- | :-- | :-- |
| `--scroll-frame-scale` | The scale the screen starts at, easing to 1 as it lies flat. | `1.05` |
| `--scroll-frame-perspective` | The distance of the viewer from the screen; smaller looks deeper. | `1000px` |
| `--scroll-frame-header-shift` | How far below its place the heading starts. | `3rem` |
| `--scroll-frame-gap` | The space between the heading and the screen. | `var(--spacing-8)` |
