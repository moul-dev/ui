`<moul-stepper>` walks the user through `<moul-step>` elements in order: sign-up, checkout, setup. Steps before `current` show a check, the connector fills up to the current step, a soft halo glides to the current indicator, and only the current step's panel shows, sliding in from the direction of travel.

## Horizontal

Each step takes a `label`, an optional `description`, and its panel as content. Drive it with your own buttons through `next()` and `previous()`. Clicking a step header also goes there.

## Validating before moving on

Before the step changes, the stepper fires a cancelable `stepchange` event with `detail: { current, previous }`. Call `preventDefault()` to keep the user where they are, and set `is-invalid` on the step to show why. Here Next does nothing until the terms are accepted.

<ComponentPreview align="stretch" stack>
<moul-stepper id="stepper-signup" data-stepper-validate>
  <moul-step label="Terms">
    <moul-checkbox is-required>I accept the terms of service</moul-checkbox>
  </moul-step>
  <moul-step label="Profile">
    <moul-text-field label="Display name"></moul-text-field>
  </moul-step>
  <moul-step label="Finish">
    <p>Your account is ready.</p>
  </moul-step>
</moul-stepper>
<div class="demo-row" style="justify-content: flex-end">
  <moul-button variant="secondary" data-stepper-previous="stepper-signup">Back</moul-button>
  <moul-button data-stepper-next="stepper-signup">Next</moul-button>
</div>
</ComponentPreview>

```js
const stepper = document.querySelector('moul-stepper')

stepper.addEventListener('stepchange', (event) => {
  const { current, previous } = event.detail
  if (current < previous) return // going back is always fine

  const step = stepper.steps[previous]
  const isValid = validate(step) // your own check
  step.isInvalid = !isValid
  if (!isValid) event.preventDefault()
})
```

`next()`, `previous()` and `goTo(index)` return `false` when the step did not change. Setting `current` from code fires no event.

## Linear and vertical

With `is-linear`, users can click back to earlier steps but not ahead of the current one; steps they cannot reach are `aria-disabled`. `next()` and `goTo()` still move forward. `orientation="vertical"` opens each panel under its own header, beside the connector. `is-disabled` takes a step out of reach, and the `icon` slot replaces the number.

On narrow screens a horizontal stepper keeps only the current step's label on screen; the others stay readable to screen readers.

## Accessibility

- The steps are an ordered list. Each header is a native `<button>` named by its label, with ", completed" or ", has an error" added when that applies, and described by its description. The current step has `aria-current="step"`.
- One step button is in the tab order. `Arrow Right` and `Arrow Left` (`Arrow Down` and `Arrow Up` when vertical) move focus between steps, wrapping, and `Home` and `End` jump to the first and last. Moving focus does not change the step; `Enter` or `Space` does, when the step is reachable.
- Steps the user cannot go to (disabled ones, and later steps in `is-linear` mode) are `aria-disabled` but stay focusable, so they can still be read.
- Every change of step is announced through a polite live region, for example "Step 2 of 4: Delivery", and focus stays where it was. The announcement is in English.
- Under reduced motion, the halo jumps, the connector fills and the panel changes at once.

## API reference

### `<moul-stepper>`

| Attribute | Property | Type | Default |
| :-- | :-- | :-- | :-- |
| `current` | `current` | `number` | `0` |
| `orientation` | `orientation` | `'horizontal' \| 'vertical'` | `'horizontal'` |
| `is-linear` | `isLinear` | `boolean` | `false` |
| — | `steps` (read-only) | `MoulStep[]` | — |

| Method | Description |
| :-- | :-- |
| `next()` | Goes to the next enabled step. Returns `false` if there is none or `stepchange` was cancelled. |
| `previous()` | Goes to the previous enabled step. Returns `false` if there is none or `stepchange` was cancelled. |
| `goTo(index)` | Goes to the step at `index`, even ahead of the current one in linear mode. Returns `false` for the current, a disabled or a missing step, or when `stepchange` was cancelled. |

| Event | Type |
| :-- | :-- |
| `stepchange` | `CustomEvent<{ current: number; previous: number }>`, cancelable |

| Slot | Description |
| :-- | :-- |
| `(default)` | The `moul-step` elements. |

**CSS parts:** `list`, `highlight`, `status`

### `<moul-step>`

| Attribute | Property | Type | Default |
| :-- | :-- | :-- | :-- |
| `label` | `label` | `string` | `''` |
| `description` | `description` | `string` | `''` |
| `is-invalid` | `isInvalid` | `boolean` | `false` |
| `is-disabled` | `isDisabled` | `boolean` | `false` |

The stepper sets `data-status` (`complete`, `current` or `upcoming`) and `data-orientation` on each step, for styling.

| Slot | Description |
| :-- | :-- |
| `(default)` | The step's panel content. |
| `icon` | A custom indicator; replaces the number, check and alert mark. |

**CSS parts:** `item`, `trigger`, `indicator`, `label`, `description`, `connector`, `connector-fill`, `panel`
